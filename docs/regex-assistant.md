# 正则助手

0.7新增，完全本地运行，无grex、模型或新增第三方依赖。它是编辑节点时的辅助界面，不是一个处理数据的新节点；正式流程和导出的exp.py只保存最后确认的表达式及相关参数。

## 使用顺序

1. 在节点的正则输入框旁点击“正则助手”。打开、测试或取消都不修改流程。
2. 选择“常用模板”，或在“规则组合”中设置固定前后缀、中间字符和长度，点击“生成表达式”。表达式也可以手动修改。
3. 填写正例（应命中）和反例（不应命中），点击“测试正反例”。模板自带一组可以修改的样例。
4. 检查误匹配、漏匹配、捕获内容或替换结果。当前配置的全部样例通过后，才可点击“回填到节点”。

修改表达式、匹配方式、捕获组、替换内容或样例之后，旧测试会标为过期，需要重新测试。回填同时更新相关参数，在画布中一次撤销即可整体恢复；取消保留原配置。

## 模板与规则组合

自带9个模板：1开头的11位手机号、18位身份证格式、无符号整数、最多两位小数的金额、常见ASCII邮箱、IPv4、日期、日期时间和十六进制字符串。

模板说明会标注限制：身份证格式不检查校验码，日期格式不检查闰年或2月30日，手机号不限制真实号段。进一步的业务检查继续连接相应校验节点。数字与IP模板在搜索/提取模式下附上必要边界，避免从更长数字或非法IP中截出一个看似合法的子串。

规则组合例如：固定前缀填`1`，中间字符选“数字0～9”，中间长度最小/最大都填`10`，得到`1[0-9]{10}`。中间长度不包含固定前后缀。

前后缀按原文转义，所以输入`.`表示一个点，不会被当作任意字符。自定义字符逐字列出；`abc_-`表示允许这5个字符，不是范围表达式。汉字选项只覆盖常用区U+4E00～U+9FFF。忽略英文大小写使用Python的ASCII大小写规则；“允许整个值为空”只额外允许空字符串，不自动去除空白。

## 与节点保持一致

| 入口 | 测试方式与回填 |
| --- | --- |
| 字段格式校验 `validate.regex` | 可切完整匹配/搜索，回填pattern和full_match |
| 组合规则校验中的正则规则 | 固定完整匹配，只修改当前规则的pattern |
| 条件筛选/条件分类中的正则条件 | 固定搜索匹配，只修改当前条件的value |
| 正则提取 `text.extract` | 根据捕获组与首个/末个匹配测试，回填pattern、group和occurrence |
| 提取全部匹配 `text.find_all` | 测试当前一条规则，跳过未参与匹配或空的捕获组，回填该规则的pattern和group |
| 查找替换 `text.replace` | 显示实际替换结果；回填search、replacement、count并启用regex |
| 多行日志 `text.records` | 按单行起始条件做搜索，回填start_pattern |

查找替换原本处于字面模式时，打开助手会先转义原查找文本，保持其含义；替换内容使用Python的`\g<1>`或`\g<name>`语法，不是JavaScript的`$1`。提取全部时只测试这一条正则，多规则之间的重叠和优先级仍需在节点预览中核对。

当前入口覆盖上述内置参数编辑器，不会自动理解外部插件或任意JSON中的正则含义。表达式不需要套`r"..."`、引号或`/.../`；前端负责配置JSON的转义。

## 样例与性能边界

- 每行一个样例，保留前后空格，空行忽略。用“空字符串预期”单独选择应命中、不应命中或不测试；要测试含换行的单元格，请用实际节点预览。
- 最多100个样例，每例最多2048字符，总计最多16384字符；表达式最多2048字符，替换文本最多256字符。
- 命中位置按Python Unicode字符索引显示，范围为`[起点, 终点)`，从0开始；每例最多展示20个命中，超过时明确标注。
- 所有匹配在独立Python子进程中执行，超时2秒后终止并回收。最多同时运行2个测试，满额返回稍后重试；不占用流程任务工作线程。
- 助手界面和样式按需加载；只在点击生成或测试时请求本地服务，不会自动扫描完整CSV，也不写附件。
- “全部样例通过”仅表示这些正反例符合预期，不代表规则覆盖所有数据，更不是赛事正确率。确认后仍应预览正式流程。

这个超时仅约束助手里的测试。正式节点沿用现有Python re执行方式，没有因此自动获得正则超时；复杂表达式应先通过长样例和边界样例检查。

## 代码与审计入口

- `frontend/src/components/RegexInput.tsx`：输入框旁入口、按需加载、取消和回填。
- `RegexAssistant.tsx` / `RegexAssistant.css`：模板、规则组合、正反例和结果界面。
- `frontend/src/regex-assistant.js`：节点匹配方式、关联参数补丁、样例保留和过期结果判断。
- `Fields.tsx` / `Inspector.tsx` / `App.tsx`：复杂规则编辑器接入、一次性更新节点参数并记录撤销。
- `datasecurity/web/regex_assistant.py`：模板、使用re.escape组合规则、请求上限、并发限制、子进程管理。
- `datasecurity/web/_regex_worker.py`：标准库re实际执行及受限结果生成。
- `GET /api/regex/templates`、`POST /api/regex/build`、`POST /api/regex/test`：本地接口；POST沿用工作区token和Origin检查。

辅助模块只位于Web层，处理节点没有导入它，因此不会被打包进独立exp.py。测试见`tests/test_regex_assistant.py`与`frontend/tests/regex-assistant.test.mjs`，包括实际节点语义对照、分组引用、超时回收、容量限制、参数联动和过期测试禁止回填。

## 本版验证

0.7.0完成107项Python测试、23项前端测试，以及TypeScript检查和生产构建。实际界面验证了手机号模板8/8通过、错误规则显示误匹配和漏匹配、修改后旧测试失效、关联参数一次回填与一次撤销、嵌套规则和Python分组替换。用界面回填后的流程生成独立exp.py，以`python -I -S`重跑，3个输出文件与原流程逐字节一致，脚本未引入助手模块。

本次生产构建中，助手按需加载的JS约10.6KB、CSS约3.4KB，主入口JS比0.6版增加约5.1KB，均为压缩传输前的文件大小。没有新增第三方依赖；这些数字只说明本次构建的体积，不代表所有流程的运行时间。
