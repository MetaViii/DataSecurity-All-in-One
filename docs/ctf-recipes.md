# 公开赛题规则与四条离线演练

本页保留最初的虚构样本演练。0.4已另外取得3道公开原题的完整附件，全部计算出与公布值一致的flag，见 [完整原题实测](real-ctf.md)。不要把这两组证据混在一起。

本页记录2026-11-04查阅的公开参赛者 Writeup。没有取得原比赛附件，也没有连接官方评分环境。仓库里的全部演练数据是自造小样本；验证的是工具执行及明确规则下的预期答案，不是“原题已解出”或“官方正确率100%”。

- [X1cT34m：羊城杯2025初赛](https://ctf.njupt.edu.cn/archives/1178)：dataIdSort 展示混杂数据的证件、电话等提取和分类。本仓库仅借其分隔格式规范化思路制作证件演练，生日/性别对照是额外教学规则；尚未重现整题混合类型分类。
- [Mak：浙江2025决赛](https://mak4r1.com/write-ups/2025%E6%B5%99%E6%B1%9F%E7%9C%81%E7%9C%81%E8%B5%9B%E5%86%B3%E8%B5%9Bwp/)：数据安全脚本涉及订单金额、银行卡校验和时间关联。本工具拆成三个可组合节点，并保留人工定义规则的边界。

公开WP可能是选手自己的解法，不能当作官方评分器规范。我们没有照搬这些项目或脚本，采用独立节点实现。

## 1. 字段还原

首页打开“演练：字段编码还原”。read → decode → 两个输出。

decode 的 fields 选 username、city；key 为公开WP中的已知值，key_offset=1，input_format=base64、output_format=text。每个字段分别从偏移1开始；第一行并不是表头加密，csv.read 已把表头取走。

小样本3行：2行还原为 `demo_a/杭州`、`demo_b/宁波`；1行含损坏Base64，整行进入 invalid，保留损坏密文。正式运行得到答案CSV和拒绝JSONL。测试逐单元格比较独立预期，不只看行数。还原2行的4个单元格全部一致；拒绝行不是被丢弃。

## 2. 证件清洗与一致性

首页打开“演练：证件清洗与一致性校验”。先显式删除题目允许的空白和连字符，再校验格式、生日、校验码及生日/性别字段。号码采用GB标准示例，不关联真实人物。

5行中001、005通过；002性别不一致、003校验码错误、004格式无效。答案保留001、005的原始顺序。每次清洗和失败原因可在记录追踪里查看。这里选择拒绝不确定记录；题目如果要求修复所有错误，应先按权威字典或明确冗余关系补全，再重新校验，不能凭校验位猜原始值。

## 3. 订单异常调查

首页打开“演练：订单异常调查”。Luhn 把坏校验码订单E分出去；窗口节点按卡号统计过去一小时的不同用户，输出A/B/C/D的计数为1/2/1/2，再标记需要调查的订单。金额节点在同品类4行中使用1.5倍总体标准差，标出D。

1.5仅用于让小样本展示异常分支；不能代替原题的3σ。WP中的 pandas std 通常使用样本标准差，本演练明确设置总体口径；节点可通过ddof=1切换样本口径。窗口闭区间包含端点和当前行，同一时刻一起算，结果回到源顺序。这些口径必须按题目核对。

这条流程只演练三类原子能力。原题可能还要求商品范围、用户行为、异常标签合并、固定规则优先级和特定提交格式；当前示例没有宣称完整实现那些判分条件。

## 4. 参考表纠错与提交

“演练：参考表纠错与提交”是独立设计的CSV纠错练习，并非某道原题复刻。脏表3行，参考表2行；按编号替换部门，001→运维、002→开发，003未命中进入审查分支。手机号脱敏后导出无表头TSV文本，另一路质量概览查看原表空值和频数。

检查的是最终UTF-8字节、换行和字段顺序，答案不是靠文件打开看起来相似。预期两行全部一致；未命中1行保留原值，不算作已修复。

## 自己重跑

```powershell
python -m unittest tests.test_ctf_recipes -v
python -m datasecurity run examples/ctf_xor.json --preview --limit 5
python -m datasecurity run examples/ctf_identity.json
python -m datasecurity run examples/ctf_orders.json
python -m datasecurity run examples/ctf_lookup.json
```

CLI正式结果放 `work/practice/`，示例开启overwrite，仅覆盖自己的同名演练结果。Web正式结果按运行ID隔离。测试用临时目录，不改用户项目。预期答案在 `examples/data/ctf_expected.json`，生成虚构附件的脚本在 `examples/build_practice_data.py`；不依赖网络。

要在真实附件上评估正确率，先明确按行、按字段还是按集合评分，是否按ID对齐，是否忽略顺序/空格、允许缺失行。现有 tables.compare 可作本地基线，但比赛评分逻辑仍需单独确认。没有参考答案时只能报告校验通过率，不能称为答案正确率。
