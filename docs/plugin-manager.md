# 从界面添加插件

顶部“插件”或节点库的“添加插件”打开管理页。可导入一个 `.py`、粘贴源码，或选择“字段处理”“校验与分流”模板。这里管理的是工作区 Python 扩展，安装后节点参数和端口由 PluginSpec 自动生成，无需再注册前端组件。

## 最短操作

1. 选模板，先读源码。
2. 改文件名、插件 ID、中文名称和 run 里的逻辑。多个自定义插件必须有不同 ID。
3. 勾选已阅读并信任，点击“安装并加载”。
4. 在节点库“全部”或搜索插件名称，添加到画布。模板使用 local. 前缀，会出现在常用列表。
5. 接输入，选字段，预览并查看修改历史，再接输出运行。

源码最大256 KiB，UTF-8；文件名以字母开头，只用字母、数字、下划线，以 `.py` 结尾。系统保留名称不能使用。安装采用独占新文件，不会覆盖同名 `.py` 或 `.py.disabled`。文件路径固定在当前工作区 `plugins/`。

模板是能运行的普通 Python。`PLUGINS = [MyTransform]` 告诉加载器要实例化哪些类。PluginSpec 声明元数据，Parameter 声明配置，run 接收输入表与已校验配置；核心类型和完整身份证样例见 `docs/plugin-development.md`。

安装和启用会立即执行模块顶层代码。插件具有当前 Python 进程权限，包括本机文件读写；勾选表示用户已审阅并信任源码。语法检查与注册检查不能替代沙箱。不要把下载来的未知代码当作数据附件安装。

## 停用、修改和恢复

停用把文件改名为 `name.py.disabled`，不删除源码。相关画布节点标为缺少插件，配置和连线保留；重新启用后恢复元数据。启用需要再次确认信任。

想修改已安装源码，可在编辑器修改 `plugins/name.py`，然后点击重新加载。也可以先下载原源码，在界面用不同文件名和不同 ID 安装新版本作比较。界面当前不提供原位覆盖、文件删除、pip安装或在线商店。

重载会执行目录里全部启用的可信模块；单文件加载失败会显示诊断，其余文件仍加载。安装或启用失败则不替换当前注册表；对应新文件不落盘，禁用文件仍保持禁用。Python 模块执行已经产生的外部副作用无法回滚，因此模块顶层只放声明，实际数据处理放 run。

有排队或正在执行的流程时，后端拒绝安装、启用、停用和重载（409）；等任务结束或取消后再操作。所有写接口仍要求本次服务会话令牌并校验来源。

## 沿代码看实现

`frontend/src/components/PluginManager.tsx` 管理源码草稿、模板、信任勾选和反馈；`plugin-manager.js` 只做浏览器预检查与目录筛选。前端校验是提示，Python 后端是最终判断。

`datasecurity/web/plugin_manager.py` 负责路径、大小、信任、安装与启停；它复制 Registry，在副本加载完整文件，成功后落盘并换注册表。Registry.copy 共享已经加载的插件实例，不重新执行其它模块。

`datasecurity/core/registry.py` 的 load_file 使用 compile/exec 读取最新源码，不依赖可能尚未过期的 pyc。先验证整文件的实例和 ID，成功后一次性注册；file_plugins/file_errors 为界面提供文件级诊断。

`JobManager.edit_plugins` 与提交任务共用一把 RLock，避免“检查时没任务，换表前又启动任务”的竞争。已完成的结果保留，但前端会标为需要重跑，因为同名插件的代码可能已经改变。

验证入口：`python -m unittest tests.test_plugin_manager -v`。覆盖模板安装运行、重复ID/文件名、信任标记、语法/模块错误、启停、重载新源码、活动任务互斥。
