# 架构与边界

当前0.7有56个内置节点和本地插件管理，支持[独立Python脚本导出](python-export.md)和[正则助手](regex-assistant.md)。节点口径见 [新增节点说明](advanced-nodes.md)、[原题实测](real-ctf.md)、[第二批实测](contest-round2.md)和[纠错评分](correction.md)；插件安装、启停的注册表切换和运行锁见 [插件管理](plugin-manager.md)。核心仍采用下述三层模型。

## 三层及依赖方向

```text
React 页面 ──HTTP──> FastAPI / 工作区 / 任务管理
                                │
CLI ────────────────────────────┤
                                ▼
                      Pipeline / Registry
                                │
                                ▼
                    Plugin + Table + Record
```

算法插件不导入 React 或 FastAPI。CLI 和 Web 共用同一套 Registry、参数校验和执行器；前端只编辑流程定义、请求执行、分页展示结果。Web 层额外管理文件位置、项目、任务生命周期和本地会话保护。

## 数据约定

`Table(columns, records)` 保存有序字段和记录元组。字段名不能为空且不可重复；每条记录的字段集合必须与表头一致。空表可以保留字段结构。

`Record` 是冻结 dataclass，`values` 在构造时复制并包成只读映射。单元格全部是字符串：`"0001"`、`""`、`"NULL"` 是不同值，不自动推断、不自动 trim。JSON 的显式 null 转为 `"null"`，缺少字段补 `""`；这是表格化约定，JSON 往返不保留原始类型。

来源 `origins`、问题 `issues`、修改 `changes` 都是不可变元组。筛选保留原 Record；修改用 `with_updates`；更改列结构用 `rebuild`，明确记录 add/drop/update。关联与聚合汇总参与记录的来源。历史记录中的旧字段名保留原貌，不随着重命名改写。

没有原地修改让分支共享数据更容易理解，也会增加大数据和长流程的内存开销。当前没有流式执行、列式存储、压缩历史或跨运行缓存。Decimal 算术使用 Python 当前默认上下文（通常 28 位有效数字），不是无限精度；输出小数会去除无意义的末尾零。

## 流程契约

```json
{
  "version": 1,
  "name": "我的流程",
  "nodes": [
    {"id": "read", "plugin": "csv.read", "config": {"path": "input.csv"}},
    {"id": "save", "plugin": "csv.write", "config": {"path": "answer.csv"}, "inputs": {"data": "read:data"}}
  ],
  "ui": {"positions": {"read": {"x": 40, "y": 60}}, "labels": {"read": "原始数据"}}
}
```

机器 ID 与显示名称分开；`inputs` 以端口名连接 `上游ID:输出端口`，不依赖连线顺序。一个输入端口只有一个上游；一个输出可以连接多个下游。执行器不读取 `ui`。重复节点、未知字段、错误参数/端口、循环连接会在读数据前报错。

`Pipeline.scope` 先选择目标和其所有祖先；`plan` 再检查参数、连线并拓扑排序。这样正在编辑的无关残缺分支不会阻止“预览所选”。全部运行会校验并执行整个图，包括未连接到导出的输入/处理节点。

所有 input/transform 成功后，才执行 output。预览直接跳过 output 插件的 `run`；输出插件有输入但没有输出端口。预览不是抽样计算：去重、唯一性、统计都针对完整范围。`rows.sample` 是流程中显式改变范围的操作。

## 文件策略

CLI 相对路径默认以流程文件所在目录为基准，`run --base-dir` 可以覆盖数据文件基准；`plugin_dirs` 仍相对流程文件，命令行 `--plugin-dir` 相对终端目录。Web 的数据路径相对工作区，解析后必须留在工作区内。

Web 上传存入 `work/uploads/`；服务只展示 uploads 与 examples/data 的直接子文件。也可以手动填写工作区内路径。每次正式运行生成随机 ID，输出文件名经过清理并改写到 `work/exports/<ID>/`；两个输出不能使用同名文件。不同运行互不覆盖。流程里的 `overwrite` 在 Web 被强制关闭。

读取插件登记 source_paths，输出插件通过 output_path 检查不能覆盖输入、不能重复写同一路径。内置输出先写目标同目录的临时文件，写完后原子替换；失败保留旧目标。多个输出没有统一事务，第二个输出失败不会撤回第一个文件。取消也可能发生在某个文件已经提交之后。

CSV 保留原文本，包括以 `=` 开头的值，不为表格软件加前缀；用 Excel 打开此类 CSV 时软件可能自行解释公式或数字。需要文本单元格时选择 XLSX 导出，XLSX 输出显式写为字符串。XLSX 读取不执行公式，默认保留公式文本；cached 需要源文件已有缓存值，reject 遇到公式报错。格式支持详见节点手册。

## Web 生命周期与并发

`Workspace` 管理路径、插件、附件元信息和项目。项目是磁盘 JSON，使用原子替换和修订号；可保存暂未连完的草稿，不在保存时强制执行校验。

`JobManager` 用单工作线程运行 Pipeline，API 不需要等完整任务结束。最多允许 3 个活动任务，逐节点回调更新状态，页面每 400ms 查询任务；结果分页每页最多 500 条，搜索先扫描完整结果再分页。前端不持有全量表。结果只在任务结束或错误后可读，完成的上游表在错误时可供检查。

任务在提交时快照流程和 Registry。重新加载插件只影响新任务。最近约 4 个完成结果留在内存；新任务会释放更早结果，旧下载链接可能失效，但文件仍可从磁盘取回。前端运行记录只是当前页面的最多 6 条摘要，服务重启后不恢复。线程中执行插件共享进程，长时间正则或库调用可能暂时无法响应取消。

## 本地服务边界

默认仅监听环回地址。TrustedHost 检查主机名；写请求需要服务启动时生成的会话 token，并检查 Origin。前端开发端口 5173 被明确允许。上传按块检查 128 MiB 限制；普通 JSON 请求通过 Content-Length 检查 2 MiB。这不是面对任意网络客户端的完整网关限流协议，也没有账号、权限组、进程隔离或资源配额。

`plugins/*.py` 在服务启动/重新加载时直接导入，插件拥有 Python 进程权限。路径检查只能约束按接口约定读写的插件，不约束任意 Python 代码。Web 不允许通过流程 JSON 注入 plugin_dirs；CLI 可以显式指定可信插件目录。表达式节点使用 AST 白名单解释器，不调用 Python eval/exec；Python 正则仍可能被复杂模式拖慢。

## 演进原则

先把题目逻辑做成可独立测试的普通函数，再包装 Plugin。只有新增交互类型时才改前端；普通节点由元数据自动呈现。只有执行协议变化时才改 core。附件规模超过内存能力时，应整体设计新的表格存储/流式协议，而不是在单个节点里悄悄抽样。
